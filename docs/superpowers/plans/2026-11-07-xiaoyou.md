# Xiaoyou Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a working Chinese Windows voice agent and localhost browser interface with real model and tool integrations.

**Architecture:** Electron hosts a React/TypeScript renderer served by a loopback Node service. Service modules own persistent data, OpenAI-compatible streaming, tool approvals and MCP, while a packaged Vosk sidecar handles offline recognition.

**Tech Stack:** Node 24, Electron, React, TypeScript, Vite, Vitest, MCP SDK, Python 3.10/Vosk/PyInstaller, electron-builder.

**Spec:** docs/superpowers/specs/2026-11-07-xiaoyou-design.md

## Global Constraints

- Windows 10/11 x64, desktop starts full screen; browser http://127.0.0.1:8765.
- Chinese UI; greeting exactly 主人，很高兴再见到你; agent/skill/wake name 小优.
- No fabricated model, weather or tool successes. Missing resources show actionable errors.
- Renderer isolated from Node. Local authenticated session, Origin validation, no API key returned.
- 对话记忆.md contains only conversation dates and actual user/assistant content; logs/config/todos separate.
- File access respects allowed workspace and symlink boundaries. Destructive, protected and external MCP actions require concrete approval.
- No shell interpolation of model-generated text. Cancellation and bounded tool loops required.
- Source run data in project; packaged run writable userData with configurable project directory.
- Use real behavioral tests, write and observe failing cases before implementation.

## File ownership and interfaces

Task 1 owns package setup, server/*.mjs and tests/service*.test.mjs. Task 2 owns src/, index.html, vite.config.ts, tsconfig.json and UI tests. Task 3 owns voice/, server/voice.mjs and scripts/voice*. Task 4 owns desktop/, scripts/build*, packaging config and README. Task 5 may fix integration defects and add end-to-end tests.

The service exports `startServer({ dataDir, projectDir, staticDir, port=8765, host='127.0.0.1', openPath?, voice? })`, resolves `{port, url, close(), runtime}`. ESM .mjs allows Electron to import without transpilation. All UI API contracts are documented in `docs/api.md` by Task 1. API JSON failures use `{error:string}` and non-2xx status. HTTP session uses HttpOnly SameSite=Strict loopback cookie; bootstrap GET creates cookie only for same-origin navigation. GET /api/state returns sanitized state. SSE POST /api/chat emits delta, tool, approval, done and error events. POST /api/approvals/:id answers a pending action. GET /api/events streams live logs and state. POST /api/settings saves model/workspace/voice/weather settings, retaining omitted key. POST /api/test-model probes actual provider. /api/todos CRUD, /api/weather, /api/mcp/reload, /api/skills update and /api/open-path as documented by Task 1. Voice WebSocket /api/voice requires same auth and Origin; Task 3 attaches through a runtime extension or callback.
