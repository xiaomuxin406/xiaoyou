# 小优：Windows 语音智能体设计

日期：2026-11-07  
状态：用户已审阅并授权实现。实际交付与验证边界见 docs/verification.md。

## 1. 目标与首版边界

交付可运行的 Windows 10/11 x64 桌面程序 `.exe`，以及复用同一界面的本机网页入口。程序名、语音唤醒名与初始 Skill 名均为“小优”。用户主要通过中文语音和文字与小优交流，并可让小优使用本机工具完成文件和应用操作。

首版由四个相互隔离的模块构成：桌面与本机服务、可视对话界面、模型与工具运行时、离线语音与本地数据。它们属于同一个可端到端验收的产品，不拆成互不连通的演示。

不提供账号系统、跨设备同步或互联网公开托管。没有 API Key 时明确提示配置模型；不冒充真实模型回答，不把天气示例当作实时天气。

## 2. 技术方案

- Electron 提供 Windows 窗口、全屏控制、系统托盘与退出管理；渲染页面不启用 Node 集成，开启上下文隔离。
- Node.js 本机服务提供 API、模型请求、Skill 加载、MCP 客户端、文件工具、天气查询和数据持久化。
- React + TypeScript + Vite 提供桌面和浏览器共用的 UI，Canvas 绘制环形星云；CSS 负责布局与面板样式。
- Python Vosk 语音辅助进程负责离线中文识别。打包时生成独立的语音辅助可执行文件，最终用户不必安装 Python。中文 Vosk 模型作为应用资源或首次配置资源提供；必须展示资源是否就绪及错误原因。
- 浏览器的 SpeechSynthesis API 或 Windows 语音能力用于中文朗读，优先选用中文语音。语音不可用时仍能文字对话，并明确显示状态。
- 单元与集成验证使用 Node/Vitest；桌面与浏览器通过自动化或实际 UI 检查；使用 electron-builder 生成 Windows 可分发产物。

## 3. 启动、窗口与网页

1. 桌面启动先初始化本机数据目录、工具注册表与服务，再打开全屏主窗口。
2. 默认地址 `http://127.0.0.1:8765`。端口可配置，端口被其他程序占用时显示明确错误，不连接到不明服务。
3. 桌面提供全屏开关、F11 切换、Esc 离开全屏；浏览器全屏遵循用户手势限制，不承诺网页打开即自动进入全屏。
4. 首次进入播放并显示：`主人，很高兴再见到你`。语音被浏览器自动播放限制拦截时，显示“启用语音”按钮，并保留文字问候。
5. 关闭桌面窗口时可选“退出程序”或“保留后台监听”；托盘提供显示主界面、麦克风开关与退出。退出时清理语音与 MCP 子进程、停止本机服务。
6. 服务仅监听回环地址。网页请求需要本机授权会话；检查 Origin，避免任意外部网页调用电脑工具。API Key 不返回给页面；设置页只显示是否已配置。

## 4. 主界面

- 默认深黑蓝背景，青蓝与紫色发光细节、轻量网格/粒子背景，中文文案。
- 顶栏展示“小优”、模型连接状态、语音状态、设置、网页入口、全屏开关。
- 左上日志面板展示实际发生的启动、应用打开、文件创建、MCP 连接与工具执行状态，并标注时间、成功或失败。密钥和隐私字段经过脱敏。
- 中央是流体环形星云：待机缓动，监听时增亮，思考时旋转，朗读时随音量或朗读进度浮动。无真实音频分析时只能使用朗读状态驱动，不声称精确音频同步。
- 星云下方显示可滚动中文对话；代码块可复制，长内容可展开，并提供停止生成。文字输入区包含发送、语音按钮与快捷提示。
- 右侧包含天气与未来预报、可新增/完成/删除的待办；数据存本机。天气城市可配置，通过地理编码与 Open-Meteo 等公开天气接口获取；未配置或联网失败时展示实际状态。
- 提供不同窗口大小的响应式布局，以及减少动画模式。不得将静态假日志和假天气充当实际数据。

## 5. 对话、模型与工具循环

### 5.1 模型配置

支持 GPT、DeepSeek、GLM 的预设与自定义 OpenAI 兼容接口，允许修改 base URL、model、API Key。服务端保存配置并发起请求，UI 不直接持有密钥。提供连接检测与明确的 HTTP/鉴权/超时错误信息。

对话采用流式输出；模型工具调用由服务端解析并执行，结果回传模型，直到生成最终回复或达到有限轮次。支持用户取消、超时与失败恢复，不无限循环。系统提示要求默认中文回答，并注入“小优”人格及已启用 Skill 内容。

### 5.2 项目 Skill

扫描项目 `skills/` 中的 `SKILL.md`，展示名称、说明、启用状态；初始文件为 `skills/小优/SKILL.md`。Skill 是给模型的操作知识和行为指引，不等同于可执行工具。

初始人格：温和、细致、表达清楚的日常助手；称呼用户为“主人”；承认不确定与失败，不伪造已经完成的操作。提供晨间安排、工作陪伴、晚间整理三个可直接对话体验的虚拟场景。虚拟场景不能伪装真实外部操作结果。

### 5.3 电脑与文件工具

首版内置读取/列出文件、创建目录、创建与编辑文本文件、打开已配置应用、读取工具目录等能力；面板可直接显示代码或其他内容。默认工作目录为当前项目或用户在设置中选择的工作目录。

普通工作目录内的新建与编辑可直接执行并记录日志。覆盖重要/受保护文件、跨出允许目录、删除文件、执行任意系统命令属于需要确认的动作；面板展示目标、内容摘要与命令后，用户接受才执行。拒绝和超时必须回传工具结果。可执行命令、文件路径和工具参数应结构化处理，避免把模型返回文本直接拼接到 shell。

### 5.4 MCP

读取项目 `mcp.json` 注册 MCP 服务，支持本机 stdio 与远端 Streamable HTTP 传输。配置遵循 MCP SDK 结构，包含 `command`、`args`、`env` 或 `url`。服务进程生命周期由小优管理。

工具列表动态发现，名称加服务前缀避免冲突，实际执行写入调用日志。调用外部 MCP 工具默认展示参数并确认；用户可把明确可信的只读工具加入允许列表。断线、超时或配置错误不阻塞普通文字聊天。没有配置时显示“暂无 MCP 服务”。

## 6. 语音交互

1. 首次启用获得麦克风权限，展示明确的麦克风状态，随时可暂停。
2. 待唤醒状态在本机识别“小优”；唤醒后进入一次语音输入，端点检测后发送文本并显示识别结果。
3. 模型回复以中文朗读；朗读时暂停唤醒监听，避免小优听到自己的声音。朗读完成后返回待唤醒状态。
4. 支持点击麦克风直接输入，以及文字发送。识别资源未就绪时文字功能仍然完整可用。
5. 桌面和本机网页均可向本机语音服务发送麦克风 PCM 音频，语音服务不默认上传音频。
6. 中文识别模型的许可证、下载来源和体积在资源说明中列出；下载失败可重试或选择本地模型目录。

## 7. 数据与记忆

源码运行时以项目根目录为数据目录。打包程序使用可写的应用数据目录，设置页提供打开数据目录的入口；通过设置选定项目目录后可加载其中的 Skill、MCP 配置与对话记忆。禁止向只读安装目录强行写入。

`对话记忆.md` 只保存对话日期和双方实际对话内容，示例：

```markdown
## 2026-11-07

用户：小优，帮我安排今天的工作。

小优：主人，我们可以先列出今天最重要的三件事。
```

不在该文件保存调用日志、系统提示、API Key、待办元数据、模型配置或音频。问候作为小优的实际对话可记录。文件采用 UTF-8 追加写入，串行写入以避免并发交错。工具日志、待办和配置分别存储。

模型上下文使用有限条最近对话，并可以读取近期记忆作为上下文；不能无限增长请求。用户可打开记忆文件审阅，不默认把全部历史发送给模型。

## 8. 模块与错误边界

- `desktop/`：Electron 主进程、预加载桥接、托盘和本机服务生命周期。
- `server/`：HTTP/WebSocket 接口、模型适配、工具执行、MCP、设置/记忆/待办/天气持久化。
- `src/`：React UI、星云绘制、语音采集与朗读、设置与确认面板。
- `voice/`：Vosk 语音辅助进程、模型管理及打包说明。
- `skills/小优/`、`mcp.json`：用户可读的能力扩展入口。
- `tests/`：核心行为与集成测试。

每个模块返回可显示的错误信息；不让语音资源、某个 MCP 或天气服务故障导致整个程序白屏。控制日志大小，避免无上限地占用磁盘。

## 9. 验证与交付验收

1. Windows 桌面可启动，全屏开关、F11 和 Esc 有效；浏览器通过默认端口打开共用 UI。
2. 初次问候的文字完全匹配；能选择中文语音并显示识别/朗读状态。
3. 配置真实 Key 后可进行中文流式对话，切换模型预设和自定义服务；未配置时不伪造回答。
4. 麦克风启用后“小优”唤醒、点击输入、文字输入均有明确状态，关闭麦克风后停止采集。
5. 模型可通过真实工具创建/编辑测试文件，日志显示成功/失败；危险操作拒绝后不能执行。
6. 可加载项目 Skill；使用本地测试 MCP 服务验证发现与调用，验证断开和拒绝处理。
7. 记忆文件仅包含日期与对话；待办重启后仍在；天气显示真实数据或明确失败。
8. 提供 README，写明启动、构建、API Key 设置、端口、数据目录、语音模型、Skill 和 MCP 扩展方法。
9. 生成 Windows `.exe` 产物并检查文件；实际语音、外部模型、天气的验证依赖本机设备与网络，交付时明确报告已验证和未能验证的项目。

## 10. 实施顺序

先打通服务与安全的数据持久化，再完成 UI 与模型对话，然后接入文件/MCP 和离线语音，最后完成桌面生命周期与打包验收。实施计划对每个可独立验证的交付划分任务，并先验证关键行为的失败用例再实现。
